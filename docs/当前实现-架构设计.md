## 2. 进程模型与安全基线

### 2.1 三进程分工

| 进程 | 职责 |
|---|---|
| 主进程（Node） | 所有 fs 操作、路径沙箱校验、工作区激活、版本管理、窗口管理、日志、自定义协议、终端 pty 会话 |
| 渲染进程（React） | 界面、编辑器、目录树、主题切换、版本对比展示、设置、xterm 终端 |
| Preload | 经 `contextBridge` 暴露受控 API（`window.mework`），不直接 require Node 模块 |

能力经 `ipcRenderer.invoke` → `ipcMain.handle` 暴露；sandbox 下 preload 仅可用 electron 内置的 `contextBridge` / `ipcRenderer`。

### 2.2 窗口安全基线

`electron/main/index.js` 的 `BrowserWindow` 配置：

- `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`、`webSecurity: true`（PRD §3.2.1）
- 外链 `setWindowOpenHandler` 仅放行 `http(s)` 交 `shell.openExternal`，一律 `deny` 新窗口
- `will-navigate` 兜底：dev 模式仅放行 dev server origin（精确比较），其余一律 `preventDefault`
- 最小窗口 720×480，`ready-to-show` 后再显示（防白屏闪烁）

### 2.3 IPC 通道清单

**单一来源 `src/shared/ipc-channels.js`**（OPT-2c：主进程 handler 与 preload 共同引用，防字符串漂移），
前缀规范（PRD §3.1.2）：`fs:` / `win:` / `term:`，预留 `agent:` / `llm:`：

| 分组 | 通道 | 用途 |
|---|---|---|
| `fs:` | `ping` | 连通性自检 |
| | `read_file` / `write_file` / `write_file_binary` | 文本 / 二进制读写（图片粘贴） |
| | `list_directory` / `list_detail` | 目录列表（`list_detail` 一次返回 name+isDirectory，4.1） |
| | `mkdir` / `rename` / `delete` | CRUD 基础 |
| | `rename_with_versions` / `delete_with_versions` | CRUD + 版本库迁移 / 清空 |
| | `stat` | 存在性 / 类型 / mtime / 大小（外部改动检测） |
| | `version_record` / `version_list` / `version_read` / `version_export` | 版本历史 |
| | `log` | 渲染层错误上报 |
| | `choose_directory` | 系统目录选择对话框 |
| | `activate_workspace` / `deactivate_workspace` / `workspace_status` | 工作区激活管理 |
| `win:` | `open_external` | 外链交系统打开 |
| | `reveal` | 资源管理器定位 / 打开（9.2.8） |
| | `get_app_version` | 动态读取版本号（9.3.5） |
| `term:` | `check_cli` / `create` / `write` / `resize` / `kill` | 终端 pty 会话（invoke） |
| | `data` / `exit` | 终端输出 / 进程退出（event 推渲染） |

## 3. 主进程模块

模块全部为「工厂函数 + 依赖注入」（PRD §3.5.1），便于单测与替换。`.mjs` 扩展名约定：electron-vite 正常打包，`node --test` 可直导入（`package.json` 保持 CommonJS 以兼容 sandbox 下 preload 的 CJS 输出）。

### 3.1 入口与窗口（`electron/main/index.js`）

- 启动时先 `registerMeworkFileScheme()`（须在 app ready 前声明特权）
- `app.whenReady()` → 注册全部 IPC handler → 注册协议 handler → 建窗口
- 窗口关闭即退出（Windows/Linux）；macOS 保留 Dock 激活重建惯例
- `win:open_external`：经 `src/shared/link-policy.js` 白名单校验（http/https/mailto/tel）后 `shell.openExternal`
- `win:reveal`：相对路径经 fs-ops `resolveAbsolute` 沙箱解析为绝对路径，再 `showItemInFolder` / `openPath`
- `before-quit`：`killAllTerminals()` 统一清理终端会话（D11）

### 3.2 pathGuard 路径沙箱（`storage/path-guard.mjs`）

工厂 `createPathGuard(root)`，以工作区根为边界，拒绝三类穿越：

- (a) 绝对路径 / 协议路径输入（`isAbsolute` + 盘符 + `scheme:` 检测）
- (b) `../` 相对穿越（resolve 归一化后校验子树前缀）
- (c) symlink realpath 逃逸（`realpathUp` 回溯最近真实存在祖先，与根 realpath 比对）

Windows 大小写不敏感（比较前统一小写）；根 realpath 惰性缓存。单测覆盖（`tests/path-guard.test.mjs`）。

### 3.3 fs-ops 受控 fs 抽象（`storage/fs-ops.mjs`）

工厂 `createFsOps(guard)`：所有 fs 操作统一经此模块（PRD §7.1，为未来 Agent 工具层预留统一入口）。方法以「相对工作区根的 relPath」为输入，先 `guard.assertSafe` 再落盘：

- 读写：`readFile`（UTF-8）/ `readFileRaw`（Buffer）/ `writeFile` / `writeFileBinary` / `appendFile`
- 目录：`listDirectory`（过滤 `.wr/`）/ `listDetail`（含类型，单项 stat 失败跳过）/ `mkdir`
- 变更：`rename` / `renameWithVersions`（版本库前缀递归迁移）/ `delete` / `deleteWithVersions`
- 查询：`stat` / `resolveAbsolute`

### 3.4 fs-context 激活边界（`storage/fs-context.mjs`）

模块级单例，解耦「工作区激活状态」与「fs 能力获取」：workspace 层在激活时 `setActiveFs(ops)`，IPC handler 统一经 `getActiveFs()` 取当前边界。未激活时抛明确错误——保证任何时刻只有一个受控 fs 边界，渲染进程无法跨工作区读写。

### 3.5 workspace-manager（`workspace/workspace-manager.mjs`）

- `activateWorkspace(absPath)`：校验存在且可访问 → 构建 pathGuard + fs-ops → 初始化 `.wr/`（实际可写性兜底，Windows 不依赖 W_OK）→ 写入 fs-context
- `deactivateWorkspace()` / `getWorkspaceStatus()`：清除 / 查询
- 最近工作区列表为 UI 偏好，由渲染进程 localStorage 管理（PRD §2.8），主进程只掌握「当前激活」边界

### 3.6 version-manager（`versions/version-manager.mjs`）

工厂 `createVersionManager(fsOps, options)`，依赖注入 fs-ops；`options` 可覆盖保留策略阈值（单测用小值验证精简）。详见《docs/阶段5-version-设计文档.md》。要点：

- 存储 `.wr/versions/<相对路径>/V{n}.md` + `meta.json`（唯一真相，编号递增不重排）
- 确定性保留策略：最近 10 版全量 + 每 10 版留 1 里程碑（`% 10 === 1`）+ 总数 > 50 才精简；幂等（先更 meta 再删快照）
- `total` 语义 = 现存快照数，非累计记版次数

### 3.7 logger 与日志轮转（`storage/logger.mjs`）

- 仅记录错误级（用户定案）；落盘 `.wr/logs/app.log`（经 fs-ops appendFile，受控）
- 9.3.4 轮转：单文件超 512KB 时删最旧备份、逐级移位（`.i` → `.i+1`）、`app.log → app.log.1`，保留最多 5 份
- 工作区未激活时仅 console；写日志失败静默，不阻断主流程；`rotateLogs` 注入 fs 便于单测

### 3.8 mework-file:// 自定义协议（`protocol/mework-file.mjs`）

- 预览相对路径图片：渲染进程将相对路径编码为 `mework-file://img/<encodeURIComponent(relPath)>`，主进程经 fs-ops `readFileRaw`（pathGuard）读取字节返回
- 特权在 app ready 前声明（standard / secure / supportFetchAPI / corsEnabled / stream）
- 畸形 `%` 序列返回 400，不存在返回 404；MIME 按扩展名映射
- 远程 `https://` / `data:` 图片不走此协议（直接 `<img>`，内容呈现，PRD §4.4.5）

### 3.9 终端（`terminal/`，CC Console）

- `terminal-manager.mjs`：工厂 `createTerminalManager({ pty })`（pty 可注入 mock），只管 pty 会话生命周期（create / write / resize / kill / killAll）；termId 由主进程生成（randomUUID）
- `cli-detect.mjs`：工厂 `createCliDetect({ run, exists, home, platform })`（依赖注入），探测 claude CLI 并返回可 spawn 的命令形态；结果模块级缓存，`invalidate()` 失效
- `ipc/term-handlers.mjs`：`term:create` 的 cwd 必经 pathGuard 沙箱解析；其余通道以 termId 寻址

### 3.10 共享模块（`src/shared/`，主 / 渲染共用）

| 模块 | 职责 |
|---|---|
| `link-policy.js` | 外链协议白名单（http/https/mailto/tel）单一来源 |
| `format-registry.js` | 文件格式注册表最小形态（OPT-2b，V1.1 前置）：`isSupportedFile` / `isSupportedExt` / `isMarkdownFile` / `NEW_FILE_SUFFIXES` / `VERSION_EXPORT_FILTERS`；目录树过滤 / 新建后缀 / 预览路由 / 版本导出 filters 统一查此 |
| `ipc-channels.js` | IPC 通道名单一来源（OPT-2c）；`agent:` / `llm:` 预留 |

## 4. 渲染进程

### 4.1 状态层

**stores**（React hooks 状态管理，无外部状态库）：

- `stores/editorStore.js`：多标签编辑器数据层（`tabs[]` + 活动标签）。每标签独立维护：`content` / `savedContent` / `diskStat`（mtime/size 快照）/ `saveState`（saved/saving/dirty）/ `error` / `loading` / `externalChange`。提供 `openFile` / `activateTab` / `closeTab` / `confirmCloseTab` / `setContent` / `save` / `close` / `renameCurrentFile` / `closeIfPathDeleted` / `rollbackTo` / `saveAll`。自动保存计时每标签独立（`autosaveTimersRef` Map，重命名时随路径迁移）。打开标签列表持久化收敛到 `openTabsStorage`（见下）
- `stores/openTabsStorage.js`（OPT-2a）：打开标签持久化单一入口——`readOpenTabs`（含旧格式迁移）+ `addOpenTab`（去重）/ `removeOpenTabs` / `updateOpenTabs` / `clearOpenTabs`
- `stores/actionRegistry.js`（OPT-3b）：应用级快捷键动作注册表——`registerAction` / `unregisterAction` / `getAction`；组件挂载时注册（每次渲染重注册持最新闭包）、卸载自动注销
- `stores/workspaceStore.js`：工作区激活状态机（restore / activate / deactivate），`activating` / `active` / 空态；最近工作区列表 localStorage

**hooks**：

- `useTheme.js`：主题三态（浅 / 深 / 跟随系统），`prefers-color-scheme` 监听，手动覆盖优先级，持久化
- `useFontSettings.js`：字体三选（Inter / 系统 / 等宽），导出 `FONT_STACKS`（含汉字回退）
- `useEditorSettings.js`：自动保存开关 / 防抖间隔 / 字号 / 终端右键入口开关（localStorage）
- `useFileTree.js`（OPT-3a）：目录树数据层——树状态（nodes / open / error / loading）与数据操作（加载 / 展开 / 刷新 / CRUD 落盘）。**在 App 持有**（3.8 评审 P1 状态提升：专注模式主/浮层 Sidebar 共享同一实例）；fs 注入；纯函数在 `utils/file-tree.js`

**utils**（渲染进程纯函数，可单测）：

- `utils/path.js`（OPT-1）：`dirOf` / `fileNameOf`
- `utils/file-tree.js`（OPT-3a）：树操作纯函数——`buildNodes` / `updateNode` / `replaceNode` / `refreshTreeNodes` / `uniqueName` / `sortNodes`（fs 注入）
- `utils/tab-state.js`（OPT-3a）：`deriveFileState`（活动标签 file 语义派生）
- `utils/markdown.js`：预览渲染管线（见 §4.3）

## 5. 关键数据流

### 5.1 工作区激活

渲染 `workspace.activate(absPath)` → `fs:activate_workspace` → 主进程校验 + 构建 guard/fs-ops + 初始化 `.wr/` + 写入 fs-context → 渲染收到 `{ok, root}` → 重置目录树（`fileTree.reset()`）→ 重新加载新工作区列表 → 恢复上次打开标签（串行）。

### 5.2 打开文件

`editor.openFile(relPath)` → 已开则激活标签；未开则新开标签（loading）→ `fs:read_file` → 记录 `diskStat` 快照 → `addOpenTab` 持久化（加载期间已关闭则不写回，P2-3）。加载失败在标签上明确报错（PRD §4.2.5）。

### 5.3 编辑 / 自动保存 / 手动保存

- 编辑：CodeMirror `onChange` → `setContent` → 更新内容与脏标记（计时器调度在 setState updater 之外，P2-1）→ 每标签独立防抖计时（默认 30s）
- 自动保存：`scheduleAutosave` 到点 → `doSave(relPath, false, 'auto')`
- 手动保存：按钮 / `Ctrl+S` → `doSave(relPath, false, 'save')`
- `doSave`：无变化不写盘 → 外部改动检测（非 force）→ 落盘 → 更新 `diskStat` → `versionRecord(editedBy)` 记版（失败静默降级）
- 切换工作区 / 批量关闭前 `saveAll()`：保存失败立即中止返回错误（OPT-1 加固），外部改动需覆盖确认

### 5.4 外部改动检测

打开时记录 `diskStat = { mtimeMs, size }`；保存前 `fs:stat` 比对——mtime 或 size 变化则设 `externalChange: true` 并阻止保存，由 UI 提示「强制覆盖并保存 / 取消」（8.4 用 stat 快照替代全量内容比对，大文件显著降 IO）。
**P2-5 定案（2026-08-16）**：stat 失败（文件被外部删除等）时保存静默重建文件，不加 UI 提示——有意行为（注释固化 + 看板「已定决策」）。

### 5.5 版本对比 / 回滚 / 导出

- 对比：`VersionPanel` 选中 1 版对「当前内存内容」，2 版对「版本A | 版本B」；主区进入只读 `DiffView`（行级 LCS，>2000 行限幅退化简单对比）
- 回滚：独立流程——确认 → 读版本内容 → 更新编辑器 → 强制落盘 → 更新快照 → 强制记 `rollback` 版（不经通用无变化跳过，避免与自动保存竞态）
- 导出：读版本内容 → 系统「另存为」（默认 Documents，工作区外；filters 由 format-registry 驱动）→ `writeFile`（pathGuard 有意豁免，用户显式选择的导出路径）

## 6. 关键实现细节

| 特性 | 实现 |
|---|---|

## 7. 扩展点（AI 预留，PRD §7）

- **fs 统一抽象**：所有读写经 `fs-ops.js`，函数签名可被未来 Agent 工具层（L0 tools）直接复用
- **模块目录预留**：`electron/main/llm/`、`electron/main/agent/`（当前仅 README 占位）
- **IPC 前缀预留**：`agent:` / `llm:`（`ipc-channels.js` 中登记）
- **格式注册表**：`format-registry.js` 为 V1.1 多文件格式支持的语言映射 / 预览形态 / 自定义后缀扩展点
- **设置页 AI 分组**：`#settings-ai` 已落地终端入口开关（CC-5），其余 AI 能力占位
- **设计原则**：不提前引入空接口（YAGNI），保持模块边界清晰、命名规范、能力抽象到位
