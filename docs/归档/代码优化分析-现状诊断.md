## 0. 总体评价

代码库规模：主进程约 1,200 行（12 个模块），渲染进程约 4,500 行（15 组件 + 2 store + 3 hook），
共享 1 模块，测试 6 个文件。

**优点（应当保持，不属于本次优化对象）**：

- 分层清晰：主进程（fs 统一入口 + pathGuard 沙箱）/ 渲染进程 / 共享模块，边界严格。
- 工厂函数 + 依赖注入贯彻（path-guard / fs-ops / version-manager / terminal-manager / cli-detect），可测性好。
- 安全基线扎实：contextIsolation / sandbox / will-navigate 精确 origin 比对 / DOMPurify 强化白名单 / 外链单一来源。
- 注释密度高且多数为「为什么」（评审编号、PRD 引用），保留了决策历史。
- lint 零告警；主进程核心模块有单测覆盖（path-guard / fs-ops / logger / version-manager / cli-detect / terminal-manager）。

**主要问题浓缩为三句话**：

1. **可读性**：Sidebar.jsx（856 行）与 editorStore.js（486 行）承担了过多职责；通用小工具（dirOf / 文件名提取 / 排序）多处复制；两套焦点圈逻辑重复；快捷键经 ref 隐式耦合。
2. **可扩展性**：文件格式判断硬编码散布 5+ 处（正撞 V1.1 格式注册表）；IPC 通道名无共享常量；打开标签持久化逻辑内联 5 处。
3. **缺陷**：发现 1 个 P1 级数据丢失缺陷（侧边栏切换工作区只保存活动标签）、若干 P2 级（setState updater 内副作用、重命名后自动保存计时器悬空、openFile 加载竞态）。

## 1. 可读性（Readability）

### R1. Sidebar.jsx 856 行 —— 上帝组件 【高优】

**现状**：`src/renderer/src/components/Sidebar.jsx` 一个组件内承担：
工作区切换菜单（含外部点击/Esc 关闭）、侧边栏拖拽调宽（3 个 resize 函数）、CLI 探测、
目录树状态与懒加载（buildNodes / updateNode / replaceNode / toggleFolder / expandNode / refreshTreeNodes / refreshBranch / refreshTree）、
树 CRUD（startCreate / submitCreate / startRename / submitRename / startDelete / confirmDelete / uniqueName）、
新建文件弹窗、版本面板入口、终端入口、资源管理器定位、快捷键动作注册（3 个）。

**问题**：任何树逻辑的改动都要在 850 行的上下文中定位；函数间依赖是隐式的（共享组件 state）；
完全无法单测（全部闭包在组件内）。

**建议**（按收益排序）：
- 树状态与 CRUD 抽成 `useFileTree` hook（输入 fs API，输出 nodes 与操作），Sidebar 只做装配；
  纯函数部分（buildNodes / updateNode / replaceNode / refreshTreeNodes / uniqueName）抽到
  `src/renderer/src/utils/file-tree.js`，可直接单测（这正是渲染进程补测试的最佳落点）。
- 拖拽调宽抽 `useDragResize`；工作区菜单抽 `useWorkspaceMenu`。

### R2. editorStore.js 486 行 —— 状态层过度膨胀 【中优】

**现状**：`src/renderer/src/stores/editorStore.js` 同时承载：标签模型（file + terminal 两类）、
打开/关闭/激活/重命名/批量关闭、自动保存计时、外部改动检测、保存/保存全部/回滚、
打开标签持久化（迁移 + 5 处内联读写）、终端会话生命周期（kill 联动）。

**问题**：
- 「打开标签持久化」读写逻辑在 `openFile` / `openTerminalTab` / `confirmCloseTab` / `renameCurrentFile` / `close`
  五处各写一遍 `readOpenTabs()` + `localStorage.setItem(OPEN_TABS_KEY, ...)`，格式细节（terminal 按 cwd+title 匹配等）分散。
- 派生状态（activeTab / currentFile / dirty / error…）用三元表达式重复判断 `activeTab?.type === 'file'` 7 次。

**建议**：
- 抽 `persistOpenTabs(mutator)` 工具（`src/renderer/src/stores/openTabsStorage.js`）：读 → 迁移 → mutator → 写，五处收敛为一处。
- 派生字段（currentFile / content / saveState / dirty / error / loading / externalChange）抽一个
  `deriveFileState(activeTab)` 纯函数。

### R3. 重复代码清单 【低优，机械替换】

| 重复点 | 位置 | 建议 |
|---|---|---|
| `dirOf`（取相对路径目录部分） | Sidebar.jsx:26、EditorPane.jsx:19 各一份 | 抽 `utils/path.js` |
| 文件名提取 `relPath.slice(lastIndexOf('/')+1)` | Sidebar.jsx:148、TabBar.jsx `fileNameOf`、EditorPane（经 fileNameOf 复用） | 同上，统一 `fileNameOf` |
| 树排序（目录在前 + `localeCompare('zh')`） | Sidebar.jsx:204、612 | 抽 `sortNodes` |
| `terminalMenuItem(null)` 生成两次 | Sidebar.jsx:727 | `const item = terminalMenuItem(null); ...(item ? [item] : [])` |
| 焦点圈 + Esc + 还原焦点（9.2.5） | ConfirmDialog.jsx 与 NewFileModal.jsx 各一套 | 抽 `useFocusTrap(maskRef, onCancel, includeSelector)` |
| 外部改动覆盖确认 | EditorPane.jsx `externalConfirm` 与 `closeExternalConfirm` 两套近重复 | **已合并（OPT-4-1，2026-08-16）**：统一状态机 `{ mode:'save' } \| { mode:'close', key }` + 单一 ConfirmDialog + 单一回调 |

### R4. 快捷键系统：ref 隐式耦合 【中优】

**现状**：`App.jsx` 全局 keydown 分发，`Sidebar` / `EditorPane` 渲染期把动作写进共享
`shortcutActionsRef.current`（newFile / newFolder / renameActive / cycleMode / closeTab）。

**问题**：
- 动作注册与组件渲染顺序隐含耦合（未注册 → 快捷键静默无效）；
- FocusOverlay 里的第二个 Sidebar 也会写同一 ref（当前不同时挂载所以无冲突，属隐患）；
- 无法单测、无法静态发现「某个快捷键无人注册」。

**建议**：改 Context（`EditorActionsProvider` 或小型 action registry：`register(key, fn)` / `unregister(key)`），
卸载自动注销，避免覆盖语义；App 只读 registry。

### R5. App.jsx props 钻探 【中优】

**现状**：Sidebar 收 12 个 props（含 tree/listOpen/listError/listLoading 四个并列 state），
FocusOverlay 原样透传；EditorPane 另收 6 个。

**建议**：
- 四个树相关 state 合并为一个 `treeState` 对象（`{ nodes, open, error, loading }`）或 Context；
- 专注模式浮层与主 Sidebar 的「同一份 props 透传」随之自然收敛。

### R6. 注释噪音 【低优】

**现状**：大量「评审 S1/P2」「9.3.4」「CC-3」等历史编号注释（如 index.js 多处、EditorPane 文件头）。
**问题**：信息量大但新读者难以过滤；历史归档已存在（docs/归档）。
**建议**：保留「为什么」与安全理由，收敛纯历史编号；不必一次性清理，随改动顺手做。

## 2. 可扩展性（Extensibility）

### E1. 文件格式硬编码散布 —— 最大扩展瓶颈，正撞 V1.1 格式注册表 【高优】

**现状**（V1.1 规划 §3.1 已定 `src/shared/format-registry.js`，但当前格式判断仍硬编码 5 处）：

| 位置 | 硬编码 |
|---|---|
| Sidebar.jsx:14-18 `isDocFile` / `DOC_EXT` | 目录树过滤：`/\.(md|txt)$/i` + 无后缀 + 点文件 |
| NewFileModal.jsx:9-20 `SUFFIX_OPTIONS` / `splitName` | 新建文件后缀限 `无后缀 / .md / .txt` |
| EditorPane.jsx:43 `isMarkdown` | 预览路由：`/\.md$/i` |
| version-handlers.mjs:36-39 | 导出版本 filters 限 md/txt |
| Sidebar.jsx:396 / NewFileModal 默认名 | 「未命名.md」默认名 |

**问题**：V1.1 注册表落地时需同时改 5 处；不落地则每一处都可能漂移（当前目录树与新建
弹窗的行为已经不一致：内联输入可输入任意后缀建文件，但非 md/txt 不会出现在树里）。

**建议**：提前收敛为 `src/shared/format-registry.js` 的最小形态（`isSupported(relPath)` / `isMarkdown(relPath)`），
三处消费点改为查注册表；V1.1 再做扩展（语言映射 / 预览形态 / 自定义后缀）。

### E2. IPC 通道名无共享常量 【中优】

**现状**：`preload/index.js` 与 `electron/main/ipc/*.mjs` 各自硬编码 `'fs:read_file'`、`'term:create'` 等字符串；
改通道名 / 加前缀靠人肉对齐。

**建议**：`src/shared/ipc-channels.js` 单一来源（与 `link-policy.js` 同模式），preload 与主进程
handler 共同引用；未来 `agent:` / `llm:` 前缀扩展点也在此登记。

### E3. version-manager 每次 IPC 调用新建实例 【低优】

**现状**：`version-handlers.mjs:16` `const vm = () => createVersionManager(getActiveFs())`，每个通道调用都 new。
**问题**：无状态所以正确，但每次调用重复闭包构造；且工作区切换后旧实例引用旧 fs-ops 的隐患不存在（getActiveFs 实时取）。
**建议**：注册时构造一次 `const vm = createVersionManager({ get ops() { return getActiveFs() } })`，
或在 workspace 激活时把 vm 实例注入 fs-context 同层。

### E4. 终端扩展点 【低优·已不错】

cli-detect（返回 `{command, args}`）+ terminal-manager（只管 pty 生命周期）职责分离得当。
观察：`term-handlers.mjs` 把「探测 claude」与「创建终端」耦合在同一通道；未来若支持多 CLI /
多 agent 类型，建议把「CLI 描述符」（探测 + spawn 形态 + 展示名）抽为可注册的 CLI 提供者。

### E5. EditorPane 条件渲染层级加深 【中优】

**现状**：`EditorPane.jsx:246` 起 `compare ? ... : isTerminal || currentFile ? ... : ...`，
终端工具条与文件工具条是两套几乎相同的 JSX（差异仅三态按钮 + 保存区）。
**问题**：新增第三种 tab 类型时分支继续加深；两套工具条重复（可读性）。
**建议**：工具条按 tab 类型拆小组件（`FileToolbar` / `TerminalToolbar`），三态按钮组抽 `ModeSwitch`。

## 3. 缺陷（Defects）

按严重度分级。P1 = 数据丢失 / 安全；P2 = 功能缺陷（可复现但影响有限）；P3 = 健壮性 / 竞态。

### P1-1. 侧边栏切换工作区只保存活动标签 → 非活动脏标签静默丢失 【必须修复】

**位置**：`Sidebar.jsx:172-186` `switchWorkspace` vs `SettingsModal.jsx:69` `handleChangeWorkspace`。

**现状**：
```js
// Sidebar（错误路径）
if (editor.dirty) {            // 仅活动标签
  const r = await editor.save() // 仅保存活动标签
  if (!r.ok) return r
}
await workspace.deactivate()
editor.close()                 // 丢弃全部标签（含其他未保存的脏标签！）
```
```js
// SettingsModal（正确路径）
const r = await editor.saveAll() // 保存全部
```

**影响**：多标签打开、其中非活动标签有未保存内容时，从**侧边栏工作区菜单**切换工作区 →
非活动脏标签内容被 `editor.close()` 静默丢弃，无任何提示。设置页「更换工作区」无此问题（saveAll）。

**修复**：Sidebar 的 `switchWorkspace` 改为 `editor.saveAll()`；遇 `externalChange` 时弹覆盖确认
（与 SettingsModal 同款状态机，或抽共用 hook `useWorkspaceSwitch`）。

### P2-1. setContent 在 setState updater 内做副作用（StrictMode 双调用）【建议修复】

**位置**：`editorStore.js:304-318` `setContent`。

**现状**：`updateTab(key, (t) => { ...; scheduleAutosave(relPath); ... })`——定时器调度发生在 updater 内部。
`main.jsx` 启用了 `<React.StrictMode>`，开发模式下 updater 会双调用 → 定时器被调度两次
（scheduleAutosave 先 clear 再 set，最终净一个，所以目前无实际 bug，但违反 React 纯函数约定，属隐患）。

**建议**：updater 内只算 `dirty`，调度放在 updater 外（先读当前 tab 或让 setTabs 回调返回 dirty 标志）。

### P2-2. 重命名后自动保存计时器悬空 【建议修复】

**位置**：`editorStore.js:384-405` `renameCurrentFile`。

**现状**：`autosaveTimersRef` 以 relPath 为 key；重命名只更新 tab 的 relPath/key，**不迁移计时器**。
若重命名时该标签有 pending 自动保存，计时器到点触发 `doSave(旧路径)` → 找不到 tab → 返回
`{ok:false, error:'标签不存在'}`，自动保存静默丢失（内容仍在 tab 里，需下次编辑或手动保存）。

**建议**：`renameCurrentFile` 中把 `autosaveTimersRef` 的 key 从旧路径迁到新路径（或 clear 后由下次编辑重建）。

### P2-3. openFile 加载完成回调无条件写回持久化列表（加载期间关闭标签的竞态）【建议修复】

**位置**：`editorStore.js:162-203` `openFile`。

**现状**：异步 `readFile` 完成后 `setTabs`（若 tab 已关则 no-op，正确）——但随后
`localStorage.setItem(OPEN_TABS_KEY, ...)` **无条件**把该文件加回持久化列表。
若用户在加载期间（loading 态）关闭了该标签，重启后该文件仍会恢复。

**建议**：写回前检查 tab 是否仍存在（`tabsRef.current.some(...)`）。

### P2-4. 终端标签持久化无去重 【低】

**位置**：`editorStore.js:207-221` `openTerminalTab`。
同一目录重复开多个终端 → 持久化列表出现多条相同 `{type:'terminal', cwdRelPath, title}` → 重启恢复出多个占位 tab。
**建议**：持久化前查重（与 file 分支的 `some()` 一致）。

### P2-5. 外部改动检测 stat 失败时静默继续保存 【已定案·保持现状】

**位置**：`editorStore.js:73-76` `doSave` 的 catch 分支。
**影响**：文件被外部删除后，用户保存会**静默重建**该文件（内容 = 内存内容）。
**定案（2026-08-16 用户拍板）**：保持现状，**不加 UI 提示**——有意行为，注释已固化
（`P2-5 用户定案：文件被外部删除后保存即静默重建，不加 UI 提示——有意行为，勿改`），
并登记《进度看板》「已定决策」区防回退。

### P3 观察项（不阻塞，记录备查）

1. `closeIfPathDeleted`（editorStore.js:409）不更新持久化打开列表——当前靠重启恢复时自愈（openFile 失败剔除），
   但会话内持久化与内存不一致。建议顺手同步。
2. `workspaceStore.activate`（workspaceStore.js:63）`setRecent(readRecent())` 绕圈读回，可直接用计算出的 next。
3. `logger.writeLog`（logger.mjs:56-73）两层 try/catch + fire-and-forget IIFE，可读性一般（行为正确）。
4. `App.jsx:141` 每次 keydown 都 `document.querySelector('.settings__mask, .confirm-dialog__mask')`——微小开销，可缓存引用。
5. `refreshTreeNodes`（Sidebar.jsx:584）对「磁盘类型变化」（目录↔文件）只更新 isDir，不重建 expanded/children 一致性——边角。
6. `FocusOverlay` 与主 Sidebar 若未来同挂载，`shortcutActionsRef` 相互覆盖（当前互斥挂载，无实际影响）。

## 5. 行动计划（按优先级）

> 原则：P1 缺陷先行（数据安全）；纯函数抽取低风险高收益；大重构（Sidebar 拆分）单独排期，避免与 V1.1 并行冲突。

| # | 动作 | 目标 | 工作量 | 风险 | 建议排期 |
|---|---|---|---|---|---|
| 1 | 修复 P1-1：Sidebar 切换工作区改用 saveAll + 外部改动确认 | 缺陷 | 小 | 低 | 立即 |
